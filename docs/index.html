The research behind the demonstration

The paper couples detailed short-horizon dynamics with a compact long-horizon representation of lane transitions. The implementation below preserves that structure with the simplifications stated here.

01

Detailed short-term motion

A four-state point-mass model describes longitudinal and lateral position and velocity. Piecewise-constant acceleration gives exact discrete dynamics.

x[k+1] = A x[k] + B u[k]
02

Continuous future transitions

Gap choices determine linear constraints on a future transition time and position. A reachable cone and a centering radius approximate later motion.

transition = (time, position)
03

Optimize the coupled plan

The future transition depends on the short-term trajectory within each QP. Explicitly enumerating discrete choices replaces a general-purpose MIQP search.

short trajectory ↔ future gap
What this recreation does and does not recover This is a simplified recreation, not the original LSTMP repository. Gap choices and three first-crossing times are enumerated; the second transition remains continuous. The study uses constant-speed traffic, conservative short-term corridors, and a simplified reachability cone. It omits SUMO, CommonRoad vehicle dynamics, the low-level NMPC, interactive braking, virtual no-transition gaps, and the original full MIQP formulation. See REPRODUCTION.md in the source archive for the equation-to-code mapping and evaluation protocol.

All six runs use the same three deterministic traffic scenes. Both methods optimize a six-second first lane change. The coupled method selects a future transition jointly; the baseline freezes its short plan before selecting the future gap.

Future transition time is a coarse planning result. Collision checks cover only the detailed six seconds at 0.02 s resolution. The combined objective trades reference-speed tracking, control effort, transition timing, and gap centering; it is not a published benchmark score.

Run the planner and inspect the results

A self-contained Python package, deterministic examples, numerical checks, and a static website. No external assets or account are required to view the demonstration. 

python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m highway_planning.experiment
python scripts/plot_results.py
python -m pytest -q
python -m http.server 8000 --directory docs

Run these commands from the repository root after cloning or extracting the source archive. Open localhost:8000 to view the page.

Python 3.9–3.12 is recommended for the pinned reproduction environment. The exported data ships with the repository, so viewing the page does not require running the optimizer. Solve times depend on the machine and solver versions.
